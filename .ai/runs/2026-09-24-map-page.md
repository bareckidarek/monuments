# Map page implementation run

## Goal

Add a real public `/map` page that renders monument markers with the existing
Leaflet adapter and bounded viewport query, keeps list/detail browsing usable
through loading, empty, and error states, and provides the legacy-inspired
bottom monument strip with a hover connection from each card to its map point.

## Scope

- Add the Leaflet browser runtime and a client map experience behind the existing
  provider-neutral adapter.
- Add a `/map` route that uses the runtime repository, demo fallback, viewport
  marker loading, retry handling, attribution, and responsive controls.
- Add a bottom monument strip and SVG connection geometry that updates on hover,
  resize, and map movement.
- Add unit and browser integration coverage for the route and core interaction.

## Non-goals

- No PostGIS, clustering library, search redesign, or map-provider-specific
  domain API.
- No legacy Angular code or direct reuse of legacy markup/assets.
- No administration, editing, or persistence of map UI state.

## Risks

- Leaflet is browser-only and must not be imported during server rendering.
- Map movement can produce frequent requests; viewport requests remain bounded and are
  serialized/debounced to avoid stale results.
- The SVG line must remain aligned after resize and map movement without blocking
  pointer input.
